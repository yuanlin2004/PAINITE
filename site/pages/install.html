Installation

Set up PAINITE

PAINITE has two parts: a server that runs the AI models on a GPU (an NVIDIA GPU, or the GPU of a Mac with Apple silicon), and the apps you use on your computers. Set up the server once, then connect each Mac or Linux computer to it.

On this page
  • 1. Install the server (or on a Mac)
  • 2. Create a token for each computer
  • 3. Install the Mac app

1. Install the server

These steps are for a DGX Spark or a Linux PC with an NVIDIA GPU. To run the server on a Mac, see Server on a Mac below.

You need: an NVIDIA DGX Spark (or another Linux machine with an NVIDIA GPU) with Docker and the NVIDIA Container Toolkit, which DGX OS includes. On other machines, the NVIDIA driver must be version 580 or newer (CUDA 13); check with nvidia-smi. You also need about 40 GB of free disk space and an internet connection for the first install. PAINITE is tested on the DGX Spark and on an x86-64 Ubuntu PC with a GeForce RTX 4070 (12 GB).

  1. Download and unpack the server on the DGX Spark:

    curl -LO https://github.com/yuanlin2004/PAINITE/releases/download/v{{version}}/painite-server_{{version}}.tar.gz
tar xzf painite-server_{{version}}.tar.gz
cd painite-server_{{version}}

  2. Run the installer:

    sudo ./install.sh

    It builds the server's Docker image, creates a private certificate so your computers can connect securely, downloads the AI models and starts the painite-server service. The first run takes a while, because it downloads NVIDIA's PyTorch image (about 20 GB) and the models (about 1 GB).

    Before it downloads the models, the installer lists each model's license and asks you to accept them. Some models allow only non-commercial use; see model licenses.

  3. When it finishes, the installer prints the server's address and its CA fingerprint, a line starting with SHA256:. Keep both for the next steps. To see the fingerprint again later:

    sudo painite-server admin fingerprint

By default the certificate covers the machine's name, name.local, and its IP addresses. If your computers reach it by another name, add it: sudo ./install.sh --hostname spark.example.lan. Run ./install.sh --help for all options.

The first few minutes after the first start are slower. On an NVIDIA GPU, the server builds faster versions of most models for your GPU in the background, which takes about 5 minutes. It checks each one against the standard model before using it, and keeps using the standard models until then, or for good if a check fails. After that, photos process up to twice as fast. Builds are kept, so later starts take seconds; after an upgrade they are rebuilt once. To turn this off, add Environment=PAINITE_ACCEL=off to the service with sudo systemctl edit painite-server.

Use the installer rather than building server/Dockerfile by hand. The Docker image holds only the server's code, not the AI models, because some model licenses don't allow bundling them. The installer downloads the models after you accept their licenses. A server without them still starts, but answers with built-in placeholders that return your photo unchanged (Upscale only resizes it), and painite status marks each model (placeholder). If you built and run the image yourself, download the models into the same data folder your server container mounts, then restart it:

docker run --rm -v /var/lib/painite:/var/lib/painite painite-server models pull --all --accept-license

Server on a Mac (Apple silicon)

The server can also run on a Mac with Apple silicon, using the Mac's GPU. It's slower than a DGX Spark, but it's an easy way to try PAINITE, and the Mac app can use a server on the same Mac. You need: macOS 14 or later, 16 GB of memory or more, about 10 GB of free disk space, and uv (brew install uv) or Python 3.11 or newer. Docker isn't needed.

  1. Download and unpack the server in Terminal:

    curl -LO https://github.com/yuanlin2004/PAINITE/releases/download/v{{version}}/painite-server_{{version}}.tar.gz
tar xzf painite-server_{{version}}.tar.gz
cd painite-server_{{version}}

  2. Run the Mac installer as yourself, not with sudo:

    ./install-mac.sh

    It installs the server with PyTorch (about 1 GB) in ~/Library/Application Support/painite-server, creates the private certificate, asks you to accept the model licenses and downloads the models, converts them to Core ML for speed (about 4 minutes), then starts the server. It starts again each time you log in. It also installs the painite-server command in ~/.local/bin; use it without sudo.

  3. When it finishes, it prints the address, https://localhost:8443, and the CA fingerprint. Continue with step 2, leaving out sudo.

By default only this Mac can use the server. To let other computers use it too, run ./install-mac.sh --lan; they then connect to https://name.local:8443. ./install-mac.sh --uninstall stops and removes the server but keeps the models, tokens and certificate. The log is in ~/Library/Logs/painite-server.log.

On an M2 Pro with 16 GB, previews take 3 to 5 seconds and a 24-megapixel photo takes 30 seconds to 2 minutes, depending on the enhancement (15 to 35 seconds on a DGX Spark). To keep everything on PyTorch instead of Core ML, set PAINITE_COREML=off in the server's environment. The server uses up to about 9 GB of memory while it works.

2. Create a token for each computer

Every computer that uses the server needs its own access token. On the server, run:

sudo painite-server token create --name my-macbook

It prints a token starting with pnt_ once. Copy it to the computer you are setting up. To see or revoke tokens later, use painite-server token list and painite-server token revoke --name my-macbook.

3. Install the Mac app

You need: a Mac with Apple silicon and macOS 14 or later.

  1. Download PAINITE_{{version}}_macos_arm64.zip, open it, and drag PAINITE to your Applications folder.

  2. Open PAINITE. This release isn't notarized by Apple yet, so macOS stops it the first time. Click Done, then open System Settings › Privacy & Security, scroll down, and click Open Anyway next to the PAINITE message. You only need to do this once.

    Or, in Terminal: xattr -dr com.apple.quarantine /Applications/PAINITE.app

  3. In the welcome window, click Connect to Server… (or choose PAINITE › Settings…). Enter the server address, for example https://spark:8443, and paste the CA fingerprint. Click Trust, then paste your token.

  4. Allow Local Network access when macOS asks. PAINITE needs it to reach your server.

Next: using the Mac app.

4. Install the command line tool

Ubuntu (x86-64 or ARM64)

curl -LO https://github.com/yuanlin2004/PAINITE/releases/download/v{{version}}/painite_{{version}}_amd64.deb   # or _arm64.deb
sudo apt install ./painite_{{version}}_amd64.deb

macOS (Apple silicon) and other Linux

curl -LO https://github.com/yuanlin2004/PAINITE/releases/download/v{{version}}/painite_{{version}}_darwin_arm64.tar.gz
tar xzf painite_{{version}}_darwin_arm64.tar.gz
sudo install painite /usr/local/bin/

For Linux use painite_{{version}}_linux_amd64.tar.gz or painite_{{version}}_linux_arm64.tar.gz. Downloading with curl as shown avoids the macOS quarantine prompt.

Connect it to the server

painite config set endpoint https://spark:8443
painite trust --fingerprint SHA256:…        # the fingerprint from step 1
painite config set token pnt_…              # the token from step 2
painite status

painite status should report the server as ok and list its models. If the models are marked (placeholder), the server has no models installed yet; see Troubleshooting. The Mac app and the command line tool share these settings, so setting up one sets up both on the same Mac.

Next: using the command line.

Upgrading

Server: unpack the new release and run sudo ./install.sh again (./install-mac.sh on a Mac). Your certificate, tokens and models are kept, and it offers to download any new models. After an upgrade, an NVIDIA server rebuilds its faster models once in the background, so jobs are a little slower for about 5 minutes, and the Mac installer converts the models to Core ML again, which takes about 4 minutes. Mac app: replace the app in Applications. Command line: install the new package the same way.

Checksums

Each download has a SHA-256 checksum on the release page. To check the command line packages: sha256sum -c --ignore-missing SHA256SUMS.
