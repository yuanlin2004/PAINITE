# PAINITE 1.3

The server is faster everywhere: up to twice as fast on NVIDIA GPUs with TensorRT and torch.compile, and up to 2.6 times faster on a Mac with Core ML. On NVIDIA, the server checks each faster model against the standard one and switches to it only if the results match.

**User guide:** https://yuanlin2004.github.io/PAINITE/ · **Speed report:** [DGX Spark, RTX 4070 and M2 Pro compared](https://github.com/yuanlin2004/PAINITE/blob/main/docs/report/2026-11-27-server-performance-dgx-spark-rtx4070-m2pro.md)

## What's new

**Faster enhancement on NVIDIA GPUs**

On a DGX Spark or a PC with an NVIDIA GPU, the server now runs most models through TensorRT (FP16) or torch.compile. A 24 MP photo, full job:

| Enhancement | DGX Spark, 1.2 → 1.3 | Speed-up on DGX Spark | Speed-up on RTX 4070 |
| --- | --- | --- | --- |
| Denoise | 32 s → 16 s | 1.98x | 2.14x |
| Sharpen | 33 s → 20 s | 1.63x | 1.91x |
| 2× upscale | 57 s → 44 s | 1.30x | 1.64x |
| Unblur, motion | 32 s → 20 s | 1.63x | 1.75x |
| Unblur, focus | 56 s → 37 s | 1.50x | 1.12x |
| Face | unchanged | 1.00x | 1.00x |

- **Results stay the same.** Before the server uses a faster model, it compares it with the standard PyTorch model on test tiles, and rejects it if it doesn't match closely (at least 50 dB PSNR, or as close as PyTorch's own FP16 path). Exports differ from 1.2 by at most a few levels in a small share of pixels, which you can't see. For example, Stripformer's TensorRT engine is wrong on a DGX Spark's GB10, so motion unblur uses torch.compile there; on an RTX 4070 the same engine passes and is used.
- **The first few minutes after installing or upgrading are slower.** The faster models are built for your GPU in the background, which takes about 5 minutes on a DGX Spark and 8 to 9 on an RTX 4070. Until then, and for any model whose check fails, the server keeps using the standard models, with jobs about 20 % slower while builds share the GPU. Builds are kept in the server's data folder (about 400 MB), so later starts take about 20 seconds.
- **A job never mixes the two.** A finished build switches in between jobs, never during one.
- **To turn it off,** add `Environment=PAINITE_ACCEL=off` with `sudo systemctl edit painite-server` and restart. The server then works exactly as 1.2 did, with identical output. `/v1/health` shows which backend each model uses.

**Faster enhancement on a Mac**

The Mac server now runs the models through Core ML where that beats PyTorch with Metal: sharpen and 2× upscale on the Neural Engine, and denoise, both unblurs and the face restorer on the GPU. A 24 MP photo on an M2 Pro (16 GB):

| Enhancement | 1.2 → 1.3 | Speed-up |
| --- | --- | --- |
| Denoise | 86 s → 56 s | 1.5x |
| Sharpen | 76 s → 29 s | 2.6x |
| 2× upscale | 109 s → 64 s | 1.7x |
| Unblur, motion | 96 s → 75 s | 1.3x |
| Unblur, focus | 158 s → 110 s | 1.4x |
| Face | 18 s → 15 s | 1.2x |

- `install-mac.sh` converts each model once from its own weights, which takes about 4 minutes, and keeps the result next to the weights. A server that finds no conversion makes one at startup, and `painite-server models coreml` redoes it by hand.
- Every tile of a photo goes through the same engine, so previews still match exports. Photos smaller than 640 px, and any model that fails to convert, stay on PyTorch.
- To turn it off, set `PAINITE_COREML=off` in the launchd agent's environment.

**Speed report**

A new report compares the server on a DGX Spark, a PC with an RTX 4070 and an M2 Pro MacBook Pro: full photos, previews, start-up time and memory. In short, the RTX 4070 is the fastest of the three, the DGX Spark is 1.1 to 1.6 times slower but has far more memory, and the M2 Pro works but is 2.3 to 8 times slower. [Read the report](https://github.com/yuanlin2004/PAINITE/blob/main/docs/report/2026-11-27-server-performance-dgx-spark-rtx4070-m2pro.md).

## Upgrading

- **Server on a DGX Spark or Linux PC:** unpack the new release and run `sudo ./install.sh` again. Your certificate, tokens and models are kept, and no new models are needed. Expect the first jobs to be a little slower for about 5 minutes while the faster models build.
- **Server on a Mac:** unpack the new release and run `./install-mac.sh` again. It adds coremltools and converts the models to Core ML, which takes about 4 minutes.
- **Mac app and command line:** unchanged apart from their version numbers, so updating them is optional.

## Before you start

- **The downloads aren't notarized yet**, so macOS blocks files downloaded in a browser. Download with `curl` as shown in the [install guide](https://yuanlin2004.github.io/PAINITE/install.html), or run `xattr -d com.apple.quarantine <file>`. For the app, click **Open Anyway** in System Settings › Privacy & Security.
- **Model licenses are separate from PAINITE's.** Motion unblur (Stripformer) is for non-commercial use only, and Focus unblur (LaKDNet) is AGPL-3.0. See [Licenses](https://yuanlin2004.github.io/PAINITE/help.html#licenses).
